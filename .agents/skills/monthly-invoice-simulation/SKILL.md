# 月度批量开票模拟

## 收齐本批输入

开始时先检查已有附件，并一次性请用户补齐这六项。已明确的值直接复用。

| 门店名称 | 本批销售总金额 | 本次票种 | 商品税率 | 金额是否含税 | 计划开票日期 |
|---|---:|---|---|---|---|
| | | 专票／普票 | | 是／否 | |

- 对账表可提供门店名和目标金额。发现左右并排的门店及金额列时，先按原金额核对门店集合、逐店差额、单侧独有记录和汇总行，再用本批指定的金额列筛选和试算。先用原金额应用用户指定的差额门槛，再逐店丢弃目标金额的小数部分。例如 994.50 元取 994 元。保留原额、整数目标和取整调整，金额来源不明确、店名为空、金额非正或取整后为零时列入异常。用户明确要求保留分位时采用原精度。
- 专票或普票逐店取用户本批最新指定的对账表。票种缺失或无法辨认时列入异常。门店抬头表只用于匹配购买方名称和税号。
- 批次共用的含税标志和计划日期可填一次。出现多个税率时，收集商品或行级对应关系。若模板没有日期字段，在核对清单记录计划开票日期。
- 另读取门店开票信息、商品历史明细，以及用户指定的导入模板（如果提供）。表内说明用于理解格式和字段，工作范围以用户当前要求为准。

## 匹配抬头与分类

- 用系统门店名、其他系统名、简称和已确认别名作精确匹配，可统一空格和全半角。保留能区分门店的地区、品牌和分店信息。找不到或匹配多个不同主体时，列出门店并请用户给出公司全称与税号，或指定开票信息表中的行。已确认的映射可复用。
- 塑料制品、纸制品等可作候选标签。正式税收分类编码来自已确认的商品映射或开票平台。材质不明、同名异品、没有确认编码的商品标记待确认，保留原商品名称。日用杂品仅用于确认属于该类的商品。

## 生成虚拟明细

将历史商品行转换成 UTF-8 JSON，保留名称、单位、历史数量和原表参考单价。目标金额与参考单价须使用同一已确认的含税口径。来源带有汇总行时，只传商品明细。按门店提供唯一 ID，ID 可用门店名或本批内部编号。

```json
{
  "products": [{"name": "示例商品", "unit": "个", "quantity": "120", "unit_price": "5.20"}],
  "targets": [{"id": "门店A", "amount": "1000.00"}]
}
```

运行 [scripts/simulate.py](scripts/simulate.py)，将输入和输出文件放在本批工作目录。

```bash
python scripts/simulate.py batch.json --output simulated.json
```

- 同一商品名称和单位合计历史数量，以该数量为权重进行不放回抽样。同商品有多个参考单价时，按各来源行的历史数量抽取一条参考单价。
- 商品种数在 1 至 5 种之间随抽样变化，上限受可用商品数限制。用户指定固定种数时可传 `--items`。保留参考单价（精确到分），每种商品的虚拟整数数量随目标金额变化，最少为 1 个计量单位。
- 脚本默认舍弃目标金额的小数，逐店返回原目标和试算目标。要保留分位时传 `--keep-cents`。需要精确对齐整数目标时传 `--tolerance 0.00`，其他容差按本批要求设置，脚本默认 10 元。多次抽样时优先接受精确结果，达到 `--attempts` 后保留容差内最接近的结果，或标为未匹配。结果记录随机种子，可传入 `--seed` 复现。

## 输出和验收

交付标明「测试用」的模拟明细表与核对异常表。模拟明细列出门店、商品、单位、历史数量、参考单价、虚拟数量、行金额、金额占比和分类。核对异常表列出每店本批票种、原金额、整数目标、取整调整、模拟合计、试算差额、匹配状态、当期参数及待补资料。验证票种与当期对账表逐店一致、行金额等于数量乘单价，并逐店复算合计和差额。未匹配门店保留目标金额和异常状态。

用户要测试导入版式时，在模板副本中使用明确标注的测试记录和相同流水号关联基本信息与明细。真实开票场景需要另从实际交易明细生成，并由用户核对抬头、编码、税率与交易金额。
